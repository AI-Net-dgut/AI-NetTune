# 答辩演示脚本（定稿版）

> 目标：8 分钟走完"发现异常 → 原因与证据 → 改参数 → 应用到仿真网络 → 观察变化 → 回滚"，并如实交代能力边界。
> 文中数值为本机实测；你的机器上可能略有差异，属正常。

## 0. 启动（两条命令）

```powershell
# 终端 A：后端（务必用 3.13 解释器；系统 python 是 conda 3.9，无 pandas）
cd F:\AI-NetTune\AI-NetTune
$env:LLM_API_KEY = "sk-你的key"        # 可选；不配也能演示，界面会标注"规则识别"
& 'D:\python\Python\Python313\python.exe' -m uvicorn main:app --host 127.0.0.1 --port 8000

# 终端 B：前端
cd F:\AI-NetTune\AI-NetTune\frontend
npm run dev          # http://localhost:5173
```

启动自检：

```powershell
curl.exe -s http://127.0.0.1:8000/api/health
```

应看到 `"prophet": true`、`"prophet_runtime": {"ok": true}`、`"kriging": true`；
如配了 key，还应有 `"llm_enabled": true`、`"llm_key_configured": true`。

## 1. 双层意图解析（先讲设计，再演示）

平台有两层意图识别，**界面会如实标注本次来源**：

| 层 | 触发条件 | 界面标注 | 特点 |
|---|---|---|---|
| 规则（主路径） | 命中关键词 | **规则识别** | 快、可离线、可复现 |
| 大模型（补充） | 规则未命中 且 已配置 key | **大模型识别** | 理解口语化表达 |

演示（两句对比，各 5 秒）：

1. 问 `为什么 AP-02 信号差` → 徽标 **「规则识别」** → 出完整研判与证据
2. 问 `帮我看看现在该关注什么` → 徽标 **「大模型识别」** → 返回模型给出的建议
   （这句已实测规则不命中，会真的调用模型）

> 讲解点：常见问法走确定性规则保证速度与稳定；规则覆盖不到的说法由大模型兜底。
> 不要宣称"每句话都靠大模型"，界面也不会那样标注。

## 2. 发现异常（1 分钟）

1. 点案例 **「AP-02 弱覆盖 01-01 10:00」** → 输入框自动填入问题（**只填不发送**）
2. 点「发送」

**预期**：结论 `覆盖故障 / 严重`，`current_state = fault_active`，右侧出现 **2 个方案**。

> 若显示"未发现明显异常"：说明该窗口确实没越阈（例如正常时段），换案例即可；这不是故障。

## 3. 原因与证据（1 分钟）

- 展开「查看指标证据」：逐分钟越阈证据 + 候选原因排序
- 强调：`rule_score` 是**规则强度，不是概率**
- 切「研判证据图」：指标趋势 / 覆盖热力图 / 连接关系 / 对象对比

## 4. 改参数并仿真（1.5 分钟）

1. 选一个方案（如"下调天线下倾角"）
2. 改参数（例如 `tilt` 8 → 5，或 `tx_power` 33 → 40）
3. 点「运行方案仿真」

**预期**：出现"仿真预计效果"对比表 + MAE/RMSE 口径说明。

> 必说：这是**同一段历史数据上的等效测算**，不是现场实测。

## 5. 应用至仿真网络（闭环，2 分钟）

1. 点「应用到仿真网络」→ 二次确认条（AP、参数、生效时刻）→ 确认
2. 状态条变绿：**生效中 · SIMCFG-xxxx**
3. 看「同段对比」表

**实测（tilt 8°→5°，生效时刻=窗口起点）**：

```
指标        原始      生效后    变化
RSRP dBm   -115.02   -111.42   +3.60
```

4. 展开「配置版本（N · 生效中）」：版本号、参数、生效时刻、应用时间

**必说三句**：

- 配置**已应用到仿真网络**，之后研判/趋势/热力图读的都是"生效后"数据；
- **原始历史没有被改写**（偏移只在读取时叠加），所以可安全回滚；
- **生效只覆盖网络 KPI；频谱预警仍基于原始频谱**，本轮未模拟配置对频谱的影响。

## 6. 预测标注与回滚（1.5 分钟）

1. 打开「预测预警」：标题旁出现绿色 **仿真配置 SIMCFG-xxxx**
2. 点「恢复原配置」→ 对比表消失、绿标变「未应用」

> 讲解点：回滚后同一窗口查询**立即**回到原始值（缓存键含配置修订号，应用/回滚会立刻失效）。

## 7. 主动交代边界（1 分钟，评委最看重这段）

| 项 | 如实表述 |
|---|---|
| 实时性 | 基于**历史回放时钟**，不是现网实时采集 |
| 预测 | 接口 10 用 Prophet（本机已验证 `ok: true`），失败会如实降级为移动平均并标注方法 |
| 空间插值 | PyKrige 克里金；26×26 网格是插值结果，**不等于每个位置都有实测** |
| 闭环范围 | 仿真内闭环（版本/生效/回滚）；**不含**真实设备下发与邻区干扰仿真 |
| 频谱 | 配置生效**不改变频谱**；界面把"网络 KPI 诊断"与"原始频谱参考风险"分开标注 |
| 误报 | 5 分钟抽样 0.29%（5/1741）；全周 1 分钟粒度 0.2047%（14 处）——两个口径不同 |
| 归因 | 候选原因按**规则强度**排序，不是概率；不宣称已确认根因 |
| 单用户 | 方案按 **AP/区域** 生成；UE 级问题会提示改用「连接分配 / 用户横向对比」 |

## 9. 现场常见卡点与处理

| 现象 | 原因 / 处理 |
|---|---|
| 「应用到仿真网络」是灰的 | 当前窗口没有方案（研判为正常或窗口太短）：换案例后再触发 |
| 点了案例右侧没结果 | 案例只改时间范围并**预填问题**，仍需点「发送」 |
| 徽标一直是「规则识别」 | 问题被关键词规则命中（规则优先）；换 `帮我看看现在该关注什么` 这类口语 |
| 每句都卡约 30 秒 | key 无效/网络不通，在等 `timeout=30` 后降级；先跑 `/api/health` |
| 配置版本显示"当前无生效" | 历史里有已回滚版本属正常；`active` 为空才是真没生效 |
| 页面能开但接口全红 | 后端没起或端口不是 8000；可设 `VITE_PROXY_TARGET` |
| 报 `No module named pandas` | 用了 conda 3.9，换 `D:\python\Python\Python313\python.exe` |
| 预测结果全是直线 | Prophet 降级为移动平均；看 `/api/health` 的 `prophet_runtime` |

## 10. 一句话总结（收尾）

> 平台把"看图找问题"变成"用自然语言提问 → 拿到带证据的结论 → 改参数并看到可解释的效果 → 可回滚的闭环"，
> 全部基于可复现的本地数据与明示的模型假设，不依赖现场网络、也不夸大能力。
