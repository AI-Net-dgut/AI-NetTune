# 答辩演示脚本（8 分钟主线）

> 目标：一条主线讲完"发现异常 → 原因与证据 → 改参数 → 应用到仿真网络 → 观察变化 → 回滚 → 预测标注"。
> 每一步都给了**预期可见结果**，现场照着念即可；数值为本机实测值，你的机器上可能略有差异（属正常）。

## 0. 准备（30 秒）

```powershell
# 终端 A：后端（务必用 3.13 解释器）
cd F:\AI-NetTune\AI-NetTune
& 'D:\python\Python\Python313\python.exe' -m uvicorn main:app --host 127.0.0.1 --port 8000

# 终端 B：前端
cd F:\AI-NetTune\AI-NetTune\frontend
npm run dev          # 打开 http://localhost:5173
```

自检：浏览器开 `http://127.0.0.1:8000/api/health`，返回 `code: 0`。
更严格的自检：`python scripts\verify_all.py --smoke --base http://127.0.0.1:8000`（应 7/7）。

## 1. 发现异常（1 分钟）

1. 进「网络工作台」→ 点案例 **「AP-02 弱覆盖 01-01 10:00」**（参考范围变为 10:00–12:00）
2. 点右侧示例 **「弱覆盖」** → 输入框自动填入问题 → 点 **发送**

**预期**：研判结论 `覆盖故障 / 严重`，`current_state = fault_active`；
回答里给出候选原因与证据（SINR/RSRP 越阈），右侧出现 **2 个处理方案**。

> 讲解点：先用自然语言提问，由 LLM/规则识别意图 → 调研判工具 → 返回证据链，而不是让人自己翻表格。

## 2. 原因与证据（1 分钟）

- 展开「查看指标证据」：看到逐分钟越阈证据与候选原因排序（`rule_score` 是**规则强度，不是概率**，如实说明）
- 切到「研判证据图」标签：指标趋势 / 覆盖热力图 / 连接关系 / 对象对比

**预期**：证据与结论同源（同一窗口、同一 AP）。

## 3. 改参数并仿真（1.5 分钟）

1. 在「处理方案与仿真」选一个方案（如"下调天线下倾角"）
2. 改参数（例如 `tx_power` 33 → 40，或 `tilt` 8 → 5）
3. 点「运行方案仿真」

**预期**：出现「仿真预计效果」对比表（原配置 vs 采用方案），带 MAE/RMSE 口径说明。

> 讲解点：仿真是在**同一段历史数据**上重算，属"等效测算"，不是现场实测——这句话必须说。

## 4. 应用至仿真网络（闭环，2 分钟）

1. 点「应用到仿真网络」→ 出现确认条（列出 AP、参数 `33 → 40`、生效时刻）→ 确认
2. 观察状态条变绿：**生效中 · SIMCFG-xxxxxxxx**
3. 看下方「同段对比」表

**预期**（实测）：

```
指标        原始      生效后    变化
RSRP dBm   -96.31    -90.01   +6.30
PRB %       26.97     16.47  -10.50
吞吐 Mbps   33.44     46.04  +12.60
```

4. 展开「配置版本（1）」：看到版本号、参数、生效时刻、应用时间

> 讲解点（关键）：配置**已应用到仿真网络**，所以之后所有图/告警/研判读到的都是"生效后"数据；
> 原始历史**没有被改写**（偏移只在读取时叠加），因此可以安全回滚。
> 生效时刻之前的分钟按原值，因此 10 分钟窗口里若只覆盖 6 分钟，delta 是"按分钟摊"后的值。

## 5. 预测标注与回滚（1.5 分钟）

1. 打开「预测预警」弹窗：标题旁出现绿色 **仿真配置 SIMCFG-xxxxxxxx**
2. 关闭弹窗 → 回到方案区 → 点「恢复原配置」

**预期**：绿标消失、对比表隐藏、状态回到「未应用」；再点「同段对比」接口会返回"没有生效配置"。

> 讲解点：闭环不等于"下发真实网络"——首页已声明不下发真实配置；接真网属后续工作（申报书"特别说明"也是这么写的）。

## 6. 边界与不夸大（1 分钟，务必主动说）

| 项 | 如实表述 |
|---|---|
| 实时性 | 观察基于**历史回放时钟**，不是现网实时采集 |
| 预测 | 趋势外推 + 阈值判定；接口 10 的 Prophet 需可写临时目录，失败会如实标 `moving_average` |
| 闭环 | 仿真内闭环（配置版本/生效/回滚），**不含**真实设备下发与邻区干扰仿真 |
| 误报 | 5 分钟抽样 0.29%（5/1741）；全周 1 分钟粒度 0.2047%（14 处），两者口径不同 |
| 归因 | 候选原因按规则强度排序，**不是概率**；不宣称已确认根因 |

## 7. 备用：一条命令的验收

```powershell

```

## 8. 现场常见卡点

| 现象 | 原因 / 处理 |
|---|---|
| 「应用到仿真网络」是灰的 | 当前窗口**没有方案**（研判为正常，或窗口过短）；先点一个案例并发送提问 |
| 点了案例但右侧没结果 | 案例只改时间范围，**不会自动提问**；点示例按钮或手输问题后点发送 |
| 对比表数值比 +6.30 小 | 生效时刻在窗口中间，只覆盖部分分钟（属正常，说明按分钟摊） |
| 预测弹窗没有绿色配置标 | 当前没有生效配置（或已回滚） |
| 页面能开但接口全红 | 后端没起，或不在 8000；也可设 `$env:VITE_PROXY_TARGET` 指到实际端口 |
| 后端报 `No module named pandas` | 用了 conda 的 3.9；换 `D:\python\Python\Python313\python.exe` |
