# 接入真实网络数据：契约、差异与工作量

> 本文回答两个问题：**现在能不能换一套真实数据跑？**（能，零代码）**要真正接现网还需要什么？**（约 1~2 周，主要是持续取数）。
> 结论先行：**当前不改代码即可接入"同契约的离线 CSV"**；接现网缺的是**持续取数通道**与**缺失维度的降级**，不是模型本身。

## 1. 零代码接入方式

| 手段 | 用法 |
|---|---|
| 换数据目录 | 设环境变量 `NETTUNE_DATA_DIR=D:\real_data` |
| 单独指定文件 | `NETTUNE_DATA_PATH=…\network.csv`、`NETTUNE_SPECTRUM_DATA_PATH=…\spectrum.csv` |
| 文件名约定 | 网络表：`network_data_30d.csv`、`network_data_7d.csv`、`network_data.csv`；频谱表：`spectrum_7d.csv`、`spectrum_30d.csv` |
| 事件表（可选） | `data/fault_events.csv`；缺省时仅少"预置案例"按钮，其余功能不受影响 |

启动时一次性载入内存（网络表 129,600 行、频谱 151 万行 / 103 MB），此后查询走内存二分索引。

**起服务前先体检**（推荐）：

```powershell
$env:NETTUNE_DATA_DIR = 'D:\real_data'
$env:PYTHONIOENCODING = 'utf-8'
& 'D:\python\Python\Python313\python.exe' scripts\doctor.py    # 校验表头、场景、时间范围、采样间隔
& 'D:\python\Python\Python313\python.exe' -m uvicorn main:app --port 8000
```

## 2. 数据契约（缺列即启动失败）

**网络表（18 列）**

```
timestamp, ap_id, ap_x, ap_y, user_id, ue_x, ue_y, rsrp, sinr, throughput,
latency, packet_loss, prb_usage, scenario, network_status,
retransmission_count, traffic_demand, active_users
```

**频谱表（9 列）**

```
timestamp, observation_id, band_id, lower_mhz, upper_mhz,
power_dbm, occupancy_pct, network_status, scenario
```

**事件表（8 列，可选）**

```
event_id, scenario, ap_id, fault_type, start_time, end_time, ramp_minutes, strength, labeled_from_expect
```

硬性约束：

- `timestamp` 为 `YYYY-MM-DD HH:MM:SS`（**北京时间、无时区**）
- 允许 UTF-8 BOM（读取用 `utf-8-sig`）
- `scenario` 必须与前端可选场景一致，否则查询返回"未知场景"
- 数值列可为字符串，但**不能空值占位导致列错位**

## 3. 真实数据与仿真数据的差异

| # | 差异 | 影响 | 零代码能否缓解 |
|---|---|---|---|
| 1 | 无 `network_status` 真值标签 | 判据照常工作，仅回测不可做 | ✅ 填 `normal` 占位 |
| 2 | 无 `ap_x/ap_y/ue_x/ue_y` 坐标 | 空间主图、热力图、IDW 插值失效 | ❌ 必须提供工参坐标 |
| 3 | 采样粒度常见 15 min / 1 h | "连续 3 分钟越阈"判据、10 分钟桶趋势失真 | ⚠️ 需重标定判据参数 |
| 4 | 数据持续增长 | 现为启动时全量载入，无增量通道 | ❌ 需新取数通道（唯一必写代码处） |
| 5 | 现网常无逐频段功率 | 频谱预警/频谱预测/频谱维研判失效 | ⚠️ 可降级为"仅网络维"，须如实标注 |

## 4. 真接现网需要写的代码（评估用，未实施）

| 模块 | 内容 | 量级 |
|---|---|---|
| 取数适配层 | 定时拉取（如 1 min）新采样并追加索引；或对接 Kafka / 数据库轮询 | 2~3 天 |
| 增量索引 | 现有 `_DF_IDX` 为静态二分索引，需支持追加 | 1~2 天 |
| 字段/单位映射 | `RSRP(dBm)`、PRB `%` vs `0~1`、吞吐 `kbps→Mbps` 等 | 半天（可配置化）|
| 缺失维度降级 | 无频谱→关闭频谱预警并标注；无坐标→关闭空间图 | 1 天 |
| 判据标定 | 采样粒度变化后重算越阈比例、连续分钟数（**须用真实标注数据**）| 1~2 天 |
| 数据质量守门 | 空值、重复、时间倒序、时钟跳变 | 1 天 |

合计约 **1~2 周**；其中判据标定必须基于真实标注，否则数字不可信。

## 5. 降级策略（缺维度时页面必须如实说明）

| 缺失能力 | 页面表现 | 禁止表述 |
|---|---|---|
| 无频谱数据 | 关闭"频谱预警/频谱预测"入口，注明"当前数据不含频谱，相关风险不可用" | 不得把网络维结论说成"频谱正常" |
| 无坐标 | 关闭空间主图与帧序列，保留趋势/拓扑/指标 | 不得用随机坐标假装有定位 |
| 采样过粗 | 告警判据旁注明"基于 N 分钟采样，'连续 M 分钟'判据已按粒度换算" | 不得沿用 1 分钟粒度下的宣传数字 |

## 6. 仿真配置（闭环）在真实数据上的语义

- 仿真生效仍只覆盖**网络 KPI**；频谱预警继续使用原始频谱（与当前一致）。
- 接入真实数据后，"应用到仿真网络"依旧是**仿真分支**，不改写原始数据、不下发设备。
- 若将来真要下发，须另行实现配置校验、灰度与回滚审计——不在本阶段范围。

## 7. 答辩口径（三句话）

1. **能接**：数据契约是 18 列标准 KPI，映射一次即可；换一套同契约 CSV 无需改代码（`NETTUNE_DATA_DIR`）。
2. **会缺**：坐标与频谱是多数现网不直接提供的维度，我们做了显式降级并在界面标注，不假装有。
3. **要写**：实时取数与增量索引属后续工作（约 1~2 周），与申报书"特别说明：后续可接入真实无线网络数据"一致。

## 8. 为什么不做"网页 CSV 上传"

上传解决的是"换一个文件"，而接现网要的是**持续取数 + 增量索引 + 判据重标定**，两者不是同一件事；
临时加上传入口会增加现场出错路径（非法文件导致演示中断），故本阶段不做。
